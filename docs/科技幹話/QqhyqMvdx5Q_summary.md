本片是 Gary Chen 對 Matt Pocock AI 開發工作流 Skill 套件 **1.3 版本**的深度拆解，重點介紹三個全新 Skill：Implement Spec、PR、以及 Retro。1.3 版本將原本「寫完代碼就結束」的開放流程升級為完整閉環：前面由 Grill-Me 把關、中間由 Implement 系列提高並行效率、結尾由 PR 負責結構化審查、Retro 負責覆盤優化。隨著 AI 寫程式越來越快，人類開發者的工作正在逐步後移——從「親自動手」移向「派工、驗收、維護環境」。

## 🔍 關鍵重點整理

### 一、舊流程回顧（5 步）
1. **Grow Me** — AI 拷問你，挖出邊界條件與盲點
2. **ToSpec** — 共識落地成規格書
3. **ToTickets** — 規格拆成獨立可驗證的任務卡（避免 Context 盲點）
4. **Implement + TTD** — 測試驅動實作
5. **Code Review** — 檢查是否符合規範

### 二、1.3 新 Skill ①：Implement Spec（Gary 最愛）

**解決的痛點**：一張 Spec 拆成 7-10 張 Tickets 時，以前要一張一張 Prompt，等完再下一張——是「人肉版的 Loop」。

**核心設計**：
- 輸入 `/implement-spec #87`，自動把所有 Tickets（88-97）按順序執行完畢
- **並行優化**：Agent 會先分析 Tickets 間的依賴關係，自動調度多隻子 Agent 在各自獨立的 Worktree 中並行施工
- 改首頁按鈕、調設定頁排版、修登入 Bug 三件事邏輯上無依賴 → 可以同時動手，時間壓縮到三分之一

> 即使不用 MAT 套件，只要在 Prompt 中要求 AI 標註 Dependency 再交給不同 Sub-agent 並行處理，一樣能提升效率。

### 三、1.3 新 Skill ②：PR（Matt 最愛）

**解決的痛點**：AI 寫程式變快了，真正瓶頸變成「人類審查 PR 的速度」。

**Matt 的 PR 規範（三段式）**：
1. **改動摘要**：用一張最小示意圖說清楚架構，不准寫廢話
2. **驗收證據**：強制 AI 附截圖或數據對比——不是嘴上說說，而是真的在背景跑測試
3. **風險評估**：標示「出事能否復原」+「影響範圍多大」，讓人幾秒內做出決策

**白話版 PR**：可根據受眾客製化——讓 AI 用生活化比喻寫給技術小白，幫助團隊成員從中累積技術 know-how。

### 四、1.3 新 Skill ③：Retro（事後覆盤）

**解決的隱藏問題**：AI 在長任務中可能默默浪費大量 Token、踩一堆沒人知道的暗坑，這些問題若不挖出來，下次開新對話同樣問題會再犯。

**覆盤兩部分**：
1. **Context Engineering 檢查**：AI 是否拿到正確的 Context？引導路徑是否足夠清晰？是否有一堆無效指令讓 Context Window 變胖？
2. **長期防護欄建立**：
   - **非黑即白的固定錯誤**（import 方式錯、檔案放錯目錄）→ 直接寫成 Lint 規則或 Pre-commit Hook，自動化攔截
   - **需要主觀判斷的事**（架構風格、程式碼品位）→ 寫進 coding standards 文件

**Matt 提醒**：千萬別把 Retro 完全自動化——讓 AI 天天自己反思會吹毛求疵，變成效率殺手而非幫手。應由人類主導定期覆盤，決定哪些優化真正值得做。

### 五、工作流完整閉環（1.3 版）

```
Grow Me（想清楚）
  → ToSpec → ToTickets
    → Implement Spec（並行執行）
      → PR（結構化審查 + 風險評估）
        → Retro（覆盤優化）
          ↺ 回到起點，循環改進
```

## 📌 核心洞察

> **AI 時代人類開發者的工作遷移**：
> - 過去：動手寫 code
> - 現在：派工 → 驗收 → 維護環境
> - 核心能力：定義問題 > 提問 > 解決問題
